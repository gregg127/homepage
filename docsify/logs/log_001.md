# log_001

## Context
The first Lighthouse audit on version `v1.0` identified several areas requiring improvement:

### Client-side Optimizations
* Reduce unused JavaScript using webpack-bundle-analyzer
* Add `<lang>` attribute to `<html>` for accessibility
* Implement gatsby-plugin-image in ImagePanel component for next-gen image formats
* Fix favicon
* Optimize photography page image sizes using gatsby-plugin-image

### Server Configuration Requirements
* Enable Brotli compression
* Implement HTTPS
* Enable HTTP/2
* Configure efficient cache policies for static assets

## Decision
I decided to split the improvements into two phases:

### Phase 1: Application-Level Fixes
The following client-side issues will be addressed immediately:
* JavaScript bundle optimization
* HTML language attribute implementation
* ImagePanel component optimization
* Favicon correction
* Photography page image sizing

### Phase 2: Server Configuration
The following server-related optimizations:
* HTTPS implementation
* HTTP/2 enablement
* Cache policy configuration
* Brotli compression

Phase 2 problems will not be fixed for now. Those are based off the environment that static page will be deployed and will be addressed later on.

* Performance score went down from >90 to <90 (excluding deleted photography page).
* Accessibility score has not changed.
* Best Practices score went up from <80 to >90.
* SEO has not changed.

Performance score went down due to the change of testing tool and deployment. Best Practices score was fixed.

### Next Steps
While Best Practices scores have improved, the decreased performance score (attributed to deployment changes) indicates the need for further optimization. These performance issues will be addressed in the next iteration.
