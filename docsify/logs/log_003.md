# log_003

## Context
As of version `v1.19`, this repository consists mainly of HTML code (99.7%) from Lighthouse reports. I want to minimize auto-generated code and focus on maintaining custom-written code in the repository.

Furthermore, the website has undergone its first major fixes, so I see no need to keep tracking the report results. The main goal now is to continue working on the Lighthouse scores and ensure there will be no regression.

## Decision
[Lighthouse CI](https://github.com/GoogleChrome/lighthouse-ci) will be used to gather performance metrics of the deployed homepage. Test reports will be stored as CI artifacts instead of in the repository.

The reports will be stored temporarily and checked manually on each application release. Repository will only contain README.md file with table containing Lighthouse scores for each version with major changes.

## Result
Performance reports are now stored in Lighthouse's temporary public storage service. The links to these reports are available in GitHub Actions workflow logs after each tag push. Test results for each page are kept for a limited time in this storage service.

The following quality gates are enforced through Lighthouse CI assertions:
- **Performance**: Minimum score of 80/100 (fails build if below threshold)
- **Accessibility**: Minimum score of 90/100 (fails build if below threshold)
- **Best Practices**: Minimum score of 90/100 (fails build if below threshold)
- **SEO**: Minimum score of 90/100 (fails build if below threshold)

These assertions ensure that any regression in critical metrics will prevent deployment, maintaining the quality standards of the website.
